# Юридические документы Boom Bala: черновики

**Это черновики для владельца и юриста, а не готовые к публикации тексты и не юридическая консультация.**
Действующая страница `/privacy` на сайте **не менялась**. Новая редакция публикуется только после (1) утверждения владельцем,
(2) юридической проверки, (3) отдельного решения о законном размещении данных (у Supabase нет региона в Казахстане).

Правила обращения с текстами:
- Везде, где нужны реквизиты или решения, стоит пометка `[ТРЕБУЕТСЯ: …]`. Их нельзя придумывать. Платформа технически не даёт
  утвердить или опубликовать документ, пока в нём есть хотя бы одна такая пометка.
- Тексты версионируются в админке (раздел «Документы»): каждое согласие хранит точную редакцию, время и способ.
- Отметка (галочка) на сайте **не является электронной цифровой подписью**. В документах это не утверждается.
- Документы не заявляют, что Boom Bala полностью освобождён от ответственности. Любые ограничения по росту, возрасту, весу
  берутся только из фактических паспортов аттракционов и правил производителей, программа их не выдумывает.

## Что нужно получить от владельца до публикации
1. Подтверждённые реквизиты оператора: Boom Bala работает через ИП «Аманов». Нужны полное ФИО по документам, ИИН, адрес регистрации и, если есть, номер уведомления/свидетельства. Это не ТОО, поэтому БИН юридического лица не используется. Реквизиты в репозитории не найдены и не придуманы.
2. Контакты оператора для обращений субъектов данных (почта/телефон/адрес) и ответственное лицо.
3. Сроки хранения для каждой категории данных.
4. Решение о месте хранения (Казахстан) и список провайдеров/получателей (Vercel, база данных, Telegram), основание передачи.
5. Решение, какой уровень данных попадает в Telegram (`TELEGRAM_NOTIFY_LEVEL=full|minimal`).
6. Фактические правила и ограничения аттракционов (из паспортов/правил площадки), порядок действий при происшествии.
7. Нужна ли в QR-форме обязательная проверка телефона. Сейчас не требуется: телефон помечается как «не подтверждён», люди с
   одинаковым номером не объединяются автоматически.

## Сверка документов с кодом (23.10.2026)
Что система фактически сохраняет при QR-регистрации; документы (согласие, политика) должны говорить именно это:

| Данные | Факт в коде |
|---|---|
| Имя | обязательно, 2–120 знаков |
| Телефон | необязателен; без него в БД `NULL`; не подтверждается |
| Количество детей | число 1–50; данных конкретного ребёнка нет |
| Согласия | отдельная строка на каждый документ: вид, номер редакции, время, способ `web_checkbox`; повтор не дублирует |
| Технические данные | `ip_hash` (хеш) и `user_agent` (до 400 знаков); при обезличивании контакта обнуляются |
| Вход | запись о входе: число детей и время; ручной вход без QR не содержит имени и телефона |
| Telegram | уровень `full` (имя и телефон заявки) или `minimal`; в профиле `kz-production` принудительно `minimal` |
| Сроки хранения | автоматическая очистка выключена, пока Owner не задаст срок (решение владельца/юриста) |

Согласие на ПДн (`personal-data-consent.md`) отделено от правил (`visit-rules.md`): отдельные документы, отдельные галочки, отдельные строки согласия. Видеонаблюдение и заявки на дни рождения в согласие QR не входят.
