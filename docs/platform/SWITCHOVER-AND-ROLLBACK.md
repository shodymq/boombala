## 0. Условия (все обязательны)
1. Владелец утвердил документы `visit_rules` и `personal_data_consent` (RU+KK, комплект 23.10.2026) и новый текст `/privacy`. Владелец решил вопросы из внутреннего перечня комплекта: Telegram в заявках на день рождения, публикации с детьми без согласий, порядок абонемента на кассе.
2. Хранение ПДн перенесено на сервер в Казахстане и подтверждено проверкой (`preflight`, `verify:roles` на казахстанской базе). Решение владельца или временный «мост» на зарубежной Supabase не заменяют это условие: Supabase (Франкфурт) для реальных ПДн не используется.
3. Документы опубликованы под Owner: `npm run legal:load -- --dir <папка> --publish` (платформа, окружение Production).

## 1. Переменные
Сайт: `LEGAL_OPERATOR_NAME`, `LEGAL_OPERATOR_IIN`, `LEGAL_OPERATOR_REG_ADDRESS` (реквизиты для `/privacy`, значения только в Vercel).
Платформа (`boombala-platform`): `PII_INTAKE_ENABLED=1`; уже заданы DATABASE_URL (роль bb_api/bb_admin), CRON_SECRET и остальные.
Сайт (`boombala`): `LEAD_PIPELINE=dual`, `CONSENT_FORM_ENABLED=1`, адрес и ключ платформы (имена — в PRODUCTION-LAUNCH-SUPABASE.md). Значения только в Vercel, тип Sensitive.
Не включать `NEXT_PUBLIC_BOOKING_CALENDAR` до внесения реальных броней.

## 2. Предполётная проверка
`npm run preflight` (платформа): роли, миграции 001–013, наличие опубликованных документов. `/api/public/legal` возвращает оба документа.

## 3. Деплой
Сначала платформа с `PII_INTAKE_ENABLED=1`, дождаться READY; затем сайт с `LEAD_PIPELINE=dual`, `CONSENT_FORM_ENABLED=1`. Переменные применяются новым деплоем.

## 4. Проверка (одна синтетическая регистрация)
1. С телефона открыть `/consent`, имя с пометкой «ТЕСТ», 3 детей, обе галочки.
2. В `/attendance` (Manager): +1 взрослый, ожидается +3, вход 0.
3. Подтвердить вход 2 детей: вошло +2, записей входа +1, взрослых без изменений.
4. В БД: по одной строке согласия на каждый документ с номером редакции; повтор запроса с тем же ключом дублей не создаёт.
5. Заявка с сайта (`dual`) видна в `/requests`; при сбое платформы приходит сообщение «ТОЛЬКО В TELEGRAM».
Тестовые записи пометить и убрать только по ключу, а не массовым удалением.

## 5. Мониторинг
GitHub Actions `health-check` (15 мин) и `outbox-retry` (5 мин) зелёные; логи Vercel без 5xx.

## 6. Откат (в этом порядке, данные не удаляются)
1. Сайт: убрать `CONSENT_FORM_ENABLED` и вернуть `LEAD_PIPELINE=telegram-only`, передеплоить (форма → 503, заявки идут в Telegram, как раньше).
2. Платформа: `PII_INTAKE_ENABLED=0`, передеплоить.
3. При необходимости: Vercel → Promote предыдущего READY-деплоя (fe6391c).
4. Записи, уже принятые, остаются в БД; экспорт `npm run db:export`.
