# Вход через Face ID / Touch ID (passkeys, WebAuthn)

Второй способ входа для сотрудников (Owner, Manager, Editor). Пароль + код из приложения остаются **запасным входом** и не менялись.
По умолчанию выключено: без `PASSKEYS_ENABLED=1` нет ни кнопок, ни страниц, ни обработчиков (они отвечают 404).

## Что это даёт
- Кнопка «Войти с Face ID / Touch ID» на странице входа: без e-mail, пароля и кода. Подтверждение лицом, отпечатком или кодом устройства.
- Тот же ключ можно использовать на странице «Подтверждение входа» после пароля.
- Ключ требует проверки человека на устройстве (`userVerification: required`), поэтому вход ключом считается пройденным вторым фактором (подходит под `MFA_MODE=required`).
- Права (RBAC), журнал, ограничения по числу ошибок и доступ только из VPN работают как раньше.

## Включение (делает администратор сервера; в Production не включалось)
1. Миграция `014_passkeys.sql` (`npm run db:migrate`), затем **роли ещё раз** (`npm run db:roles`), затем `npm run preflight`. Без миграции включать нельзя: preflight скажет `passkeys_enabled_but_migration_014_missing`.
2. В `admin.env` (только админка, не в `api.env` и не в `site.env`):

   | Переменная | Значение |
   |---|---|
   | `PASSKEYS_ENABLED` | `1` |
   | `WEBAUTHN_RP_ID` | имя хоста админки, без схемы и порта, например `admin.example.kz` |
   | `WEBAUTHN_ORIGINS` | точные адреса через запятую, **https**, например `https://admin.example.kz` (в профиле `kz-production` другой схемы нельзя) |
   | `WEBAUTHN_RP_NAME` | необязательно, подпись в окне устройства (по умолчанию «Boom Bala») |

3. Требования, которые приложение проверяет само (иначе админка в профиле `kz-production` не запустится, коды без значений в журнале): RP ID — имя хоста; каждый origin — https, без пути и логина, внутри RP ID. RP ID и origin берутся **только из окружения**, не из запроса.
4. Нужен **действующий HTTPS-сертификат** на адрес админки (в VPN-сети тоже): без него браузеры не дают создать ключ. Имя хоста, на котором ключ создан, нельзя менять: ключ привязан к RP ID (смена имени = ключи придётся добавить заново).
5. Перезапустить `bb-admin`. Откат: `PASSKEYS_ENABLED=0` и перезапуск; данные ключей остаются в БД.

## Для сотрудника
- **Добавить устройство:** войти по паролю и коду → «Мой пароль» → блок «Face ID / Touch ID» → название → «Добавить это устройство» → подтвердить лицом/отпечатком. Можно добавить до 10 устройств (телефон, ноутбук, аппаратный ключ).
- **Войти:** страница входа → «Войти с Face ID / Touch ID». На iPhone/Mac ключ синхронизируется через связку ключей iCloud.
- **Потерял телефон:** сам — «Мой пароль» → «Отозвать» у этого устройства (с другого устройства). Если войти нечем — Owner: «Сотрудники» → «Отозвать все ключи» (завершает и его открытые сессии).
- **Потерял всё и у Owner:** на сервере `DATABASE_URL=... npm run passkeys:revoke -- --email <почта>` (аудит: «server_console»), затем вход по паролю и коду (или `npm run user:mfa-reset`, если потерян и код). Ключ потом добавляется заново.

## Безопасность в двух словах
- В базе только открытый ключ, идентификатор и счётчик: по выгрузке войти нельзя. Отозванный ключ больше никогда не входит (запись остаётся в истории).
- Одноразовый вызов (challenge) живёт 5 минут в БД и погашается при первом же ответе. Чужой origin, чужой RP ID, ответ без проверки человека, откат счётчика (копия ключа), чужой ключ на странице второго фактора — отказ.
- Ошибки входа ключом считаются в том же ограничителе, что и неверные пароли (5 попыток на адрес за 15 минут), не больше 20 открытых вызовов на адрес.
- Журнал аудита: `passkey.registered`, `passkey.revoked`, `passkey.revoked_all`, `auth.login` (с пометкой «passkey»), `auth.passkey_failed`, `passkey.register_failed`.
- Обработчики `/api/webauthn/*` живут только в админке (роль `admin`, VPN), требуют точный Origin, JSON и не принимают запросов из роли `api`.

`npm test` (22 новых теста: конфигурация, регистрация, вход, повтор, origin/RP ID, счётчик, ограничитель, отзыв, права), `npm run e2e:passkeys` (настоящий Chromium с виртуальным аутентификатором: регистрация, вход без пароля, страница второго фактора, отзыв, отзыв Owner'ом, запасной вход, защита обработчиков), `e2e:isolation`, `e2e:kz-flow`. Safari на iPhone (симулятор iOS 26): кнопка и системное окно ключа открываются; создание ключа в симуляторе недоступно без iCloud, его нужно проверить на настоящем iPhone.
