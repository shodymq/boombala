# Переход на Supabase PostgreSQL: что меняется относительно Этапа 1

Решение владельца: **без собственного VPS на текущем этапе**. Публичный сайт и отдельная закрытая админка на Vercel,
PostgreSQL на Supabase (для разработки и MVP). CRM и клиентская база остаются.

> **Юридическая оговорка.** У Supabase нет региона хранения в Казахстане. Размещение персональных данных граждан РК за
> рубежом **нельзя объявлять соответствующим законодательству РК**. Пока нет отдельного решения о законном размещении
> (юридическая консультация, возможный перенос базы в РК), платформа **не собирает персональные данные в production**:
> приём заявок и QR-регистраций в базу выключен флагами (см. ниже). Реальные данные клиентов в Supabase не загружаются.
> Разработка и тесты идут на локальном PostgreSQL и на тестовых данных.

## 1. Принцип: обычный PostgreSQL, Supabase только как хостинг

Платформа **не использует Supabase SDK, PostgREST, Auth, Storage и Realtime**. Она подключается к базе обычным драйвером `pg`.
Поэтому код остаётся прежним, а миграции работают на любом PostgreSQL 15+ (в том числе на будущем сервере в Казахстане).
Ключи `anon` и `service_role` платформе **не нужны и нигде не используются**.

## 2. Аудит совместимости Этапа 1 с Supabase

| Область | Находка | Решение |
|---|---|---|
| Таблицы в схеме `public` | Supabase публикует `public` через Data API (PostgREST): без защиты таблицы читаемы по ключу `anon` | Миграция `003`: всё переносится в закрытую схему `bb` (не входит в «exposed schemas»), на каждой таблице `ENABLE ROW LEVEL SECURITY` без политик (запрет по умолчанию), отзыв прав у `PUBLIC`, `anon`, `authenticated`. Роли учитываются условно (на обычном PostgreSQL их нет) |
| Новые таблицы в будущем | Можно забыть включить RLS | Тест проходит по **всем** таблицам схемы `bb` и падает, если RLS выключен или есть права у `anon`/`authenticated` |
| `search_path` | Транзакционный пул Supavisor не сохраняет `SET` между запросами | Все запросы в коде **квалифицированы схемой** (`bb.users`, …), ничего не зависит от `search_path` |
| Пул соединений | Serverless на Vercel плодит соединения | Приложение использует строку **Transaction pooler** (порт 6543), небольшой пул на экземпляр, короткий idle-таймаут |
| Таймаут запроса | `statement_timeout` как параметр запуска соединения не поддерживается пулом | Таймаут ставится `SET LOCAL` внутри транзакции / через запрос, не стартовым параметром |
| Миграции | `pg_advisory_lock` и DDL-транзакции требуют сессии | Миграции идут только по **прямому/сессионному** подключению (`MIGRATION_DATABASE_URL`), не через транзакционный пул |
| Транзакции `BEGIN…COMMIT` | В транзакционном режиме одна транзакция = одно серверное соединение | Совместимо, ничего не менялось; запрещены `LISTEN/NOTIFY`, сессионные advisory locks и именованные prepared statements в рантайме (не используются) |
| TLS | Supabase требует TLS | Строка подключения с `sslmode=require`; в коде `ssl: { rejectUnauthorized: true }` при удалённой БД |
| Расширения | Не используются (`gen_random_uuid` встроен с PG13) | Без изменений |
| Бэкапы | На бесплатном тарифе нет ежедневных бэкапов с PITR, проект может быть приостановлен при неактивности | Для рабочего использования нужен платный тариф (уточнить актуальные условия); до этого дампы `pg_dump` по расписанию |

## 3. Размещение (новая схема)

```
Посетитель ──> boombala.kz (Vercel, проект «site»)
                  │  server-to-server, Bearer PLATFORM_INTAKE_TOKEN (только при включённых флагах)
                  ▼
Сотрудники ──> адрес админки (Vercel Preview `*.vercel.app`; в Production отдельный домен за VPN, см. ADMIN-ISOLATION-KZ.md)
                  │  pg по Transaction pooler (TLS)
                  ▼
              Supabase PostgreSQL (схема bb, RLS, Data API отключить)
```

- **Сессии и cookies.** Админка живёт на своём origin; cookie `__Host-bb_session` (HttpOnly, Secure, SameSite=Lax) ставится
  только этим origin. Сайт обращается к платформе **с сервера** (не из браузера), поэтому сторонних cookie и CORS для ПДн нет.
- **Права.** Проверка на сервере в каждой странице/действии (Этап 1). База дополнительно закрыта от Data API через RLS.
- **Секреты.** `DATABASE_URL`, `MIGRATION_DATABASE_URL`, `PLATFORM_INTAKE_TOKEN`, `CRON_SECRET`, `TELEGRAM_BOT_TOKEN` лежат только в
  переменных окружения Vercel (Sensitive), без `NEXT_PUBLIC_`. В браузер не попадает ничего.
- **IP клиента.** На Vercel берётся `x-vercel-forwarded-for` / `x-forwarded-for` (их выставляет платформа).

## 4. Что нужно сделать в Supabase (чек-лист владельца)

1. Создать проект (регион выбрать с учётом задержек; региона в РК нет).
2. **Settings → API → отключить Data API** (или оставить только пустую `public`) и не копировать `anon`/`service_role` в проекты.
3. Скопировать строки подключения: *Transaction pooler* → `DATABASE_URL`, *Direct/Session* → `MIGRATION_DATABASE_URL`.
4. Выдать пароль БД только Vercel (Sensitive) и локальной разработке для **тестового** проекта.
5. **Не** загружать реальные данные до решения о законном размещении.

## 5. Оценка трудозатрат и рисков

| Блок | Оценка |
|---|---|
| Адаптация под Supabase (схема `bb`, RLS, пул, миграции, тесты, документация) | 1,5–2 дня |
| CRM-ядро: контакты, заявки, согласия, юридические документы, outbox + Telegram | 3–4 дня |
| Экспорт CSV/XLSX с правами и защитой от formula injection | 1 день |
| Админка CRM (поиск, фильтры, карточка, экспорт, документы) | 2–3 дня |
| QR-форма `/consent` и подключение сайта (режимы, идемпотентность) | 1,5–2 дня |
| Календарь бронирований, затем новости | 4–5 и 2 дня (следующие этапы) |

Риски: **юридический** (зарубежное хранение ПДн, передача в Telegram) — главный и блокирующий для production; пул соединений и
лимиты бесплатного тарифа; Vercel Cron на бесплатном тарифе редкий (повтор уведомлений опирается ещё и на «попутную»
отправку и внешний планировщик); увеличение числа секретов; зависимость от внешнего провайдера (нужен план выхода: `pg_dump` →
сервер в РК, миграции совместимы).

## 6. Флаги безопасности (по умолчанию всё выключено)

| Флаг | Где | По умолчанию | Смысл |
|---|---|---|---|
| `PII_INTAKE_ENABLED` | platform | `0` | Платформа не принимает персональные данные (заявки, QR) |
| `LEAD_PIPELINE` | site | `telegram-only` | Текущий процесс сайта без изменений |
| `CONSENT_FORM_ENABLED` | site | `0` | `/consent` показывает «временно недоступно» и ничего не собирает |

Включение — только после отдельного решения о законном размещении и подтверждения владельца.
