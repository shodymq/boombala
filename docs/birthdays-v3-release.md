# Дни рождения: Pricing V3 — release runbook

Утверждённая Pricing V3 (18.11.2026). Источник данных сайта: `src/data/birthday-packages-v3.json`.
Торт не входит ни в один пакет. Программа «вынос торта» остаётся частью церемонии, сам торт не обещается.

## Состояние на момент подготовки
- Активных пакетов сейчас: HAPPY, STAR, BOOM BALA (новые). Старые (WOW, MAGIC, старый BOOM) не продаются для новых бронирований.
- Онлайн-приглашение: обещание пакета BOOM, функция **не реализована** (см. «Блокеры»).

## Почему порядок такой
Старый сайт в проде шлёт старые ID. Если убрать старые пакеты до переключения сайта, заявки начнут отклоняться.
Поэтому миграция ничего не выключает, а вывод из продажи — отдельный шаг **после** переключения сайта.

## Шаги выпуска (платформа, затем сайт)
0. **Снимок до релиза** (точка отката):
   `npm run catalog:snapshot -- /secure/path/catalog-before.json`
   Файл содержит только id пакетов и флаги продажи, без персональных данных. Хранить вне репозитория.
1. **Резервная копия БД** (`npm run db:export`) и проверка копии на отдельной базе.
2. **Миграции:** `npm run db:migrate` (015 — маркер схемы, без изменения данных).
3. **Каталог:** `npm run db:seed` — добавляет три новых пакета и их цены (будни/выходные) из данных сайта. Повторный запуск ничего не дублирует.
4. **Роли:** `npm run db:roles`.
5. **Проверка готовности:** `npm run preflight` — должен быть `OK`. Старые пакеты при этом могут оставаться в продаже.
6. **Переключение сайта:** деплой сборки V3 (`NEXT_PUBLIC_GA_ID` — только если нужна аналитика). Сначала платформа, потом сайт.
7. **Проверка трёх пакетов в живом окружении:** `/birthdays`, `/kk/birthdays`, одна тестовая заявка с пометкой «ТЕСТ» на каждый пакет, проверка сообщения менеджеру.
8. **Вывод старых пакетов:** `npm run catalog:retire-legacy` (идемпотентно, пишет аудит).
9. **Финальная проверка:** `npm run preflight:final` — должен быть `OK`.
10. Старые ссылки и открытые вкладки: устаревший ID получит сообщение «пакет больше не продаётся», а не подмену.

## Откат (репетирован автоматически: `platform/tests/catalog-release.test.ts`)
1. Вернуть предыдущий деплой сайта (старые ID снова отправляются).
2. Восстановить флаги продажи из снимка и снять новые пакеты с новых продаж:
   `npm run catalog:restore -- /secure/path/catalog-before.json --deactivate-current`
   Команда меняет только `is_active`. Не удаляет бронирования, созданные после V3, не трогает цены и историю правил, суммы существующих заказов не меняет.
3. Проверить, что старый сайт снова принимает заявки на старые пакеты.
Бронирования, созданные под V3 до отката, остаются с их суммой и названием пакета.

## Что проверено автоматически
- `platform`: 299/299 тестов. В том числе: репетиция релиза и отката с бронированием V3 до отката (10/10), цепочка Telegram на локальном mock (8/8: доставка, дубль, недоступность, повтор из очереди, отказ чата), ценообразование трёх пакетов в будни и выходные (7/7).
- `site`: `test:birthday-packages` 11/11, `test:funnel` 8/8, `test:lead-api` 17/17, `test:lead-form` 392/392 (ALL OK).
- Сквозная заявка сайт (`LEAD_PIPELINE=strict`) → платформа → CRM: строки в CRM с `star-party` и `boom-bala-party`, дата, слот, число детей верные.
- Переполнения по горизонтали нет: 320, 390, 1440 px, RU и KZ.

## Не проверено (нужно до публикации)
- **Telegram в реальном чате:** отправка проверена на локальном mock-сервере. Реальный бот и чат не использовались.
- **Казахский текст:** смысловая эквивалентность проверена при переводе; нужна проверка носителем языка.
- **Физические устройства:** iPhone Safari, Android Chrome; WebKit (Safari) не проверен на реальном движке.
- **Юридические страницы:** `test:legal-pages` — 4 проверки BLOCKED. Нужна утверждённая редакция правил из CRM (тест ждёт 9 разделов RU/KZ). Заглушку с выдуманным текстом я не публикую.

## Блокеры продакшена
1. **Онлайн-приглашение (BOOM):** нет генератора, нет страницы, нет действия менеджера. Публичное обещание не выполнимо до реализации. Минимальный вариант: таблица приглашений в платформе, привязанная к бронированию (имя именинника, дата, время, комната), ссылка с неугадываемым токеном, страница `/invite/<токен>` на сайте, срок действия до даты события + 1 день. Требуется решение владельца по объёму.
2. Telegram-доставка в реальный чат не подтверждена.
3. Казахский текст — нужна проверка носителем.
4. Слияние с веткой `feat/webauthn-passkeys` (PR #30): конфликты в `platform/src/core/preflight.ts`, `scripts/test-consent-form-mobile.mjs`, `src/components/consent/ConsentForm.tsx`. Нужна ручная интеграция и повторный прогон тестов обеих веток.

## Вопросы владельцу
- Торт: подтверждено — не входит ни в один пакет.
- Онлайн-приглашение: делаем сейчас или сохраняем обещание с ручной отправкой до реализации?
- Старая цена BOOM в ТЗ (114 900 / 80 430) не совпадает с живым сайтом (79 990 / 55 930): подтвердить, что выводим именно живые значения.
- Питание, доплаты за дополнительных гостей, праздничные даты и их цены.

- Казахская версия: вся оболочка (шапка, навигация, подвал, форма, WhatsApp) и страница дней рождения на казахском. Целевые страницы RU (аттракционы, меню, правила) остаются русскими; ссылки на них подписаны по-казахски.
- Календарь доступности (`AvailabilityPanel`) включается флагом; при включении его нужно локализовать.
- Фото комнат — текущие изображения сайта (созданы на основе фото, как написано на сайте).
