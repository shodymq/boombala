# Дни рождения: Pricing V3 (HAPPY, STAR, BOOM BALA PARTY)

Версия: утверждённая Pricing V3 (18.11.2026). Источник данных: `src/data/birthday-packages-v3.json` (копия `packages.json`).

## Что изменилось
- Сайт: три активных пакета, сравнение, карточки, форма заявки, FAQ, главная; казахская страница `/kk/birthdays`.
- Форма заявки: казахский интерфейс и казахские ошибки при открытии с `/kk/birthdays`.
- API заявки: пакеты из конфига; устаревший ID (WOW, MAGIC, старый BOOM) получает понятную ошибку, а не подмену.
- Платформа: миграция `015_birthday_packages_v3.sql` деактивирует три старых пакета (строки и история цен сохраняются); `db:seed` добавляет новые; preflight проверяет оба шага.

## Порядок выпуска (обязательный)
1. Резервная копия БД (`npm run db:export`) и проверка копии.
2. Платформа: `npm run db:migrate` (применится 015) → `npm run db:seed` → `npm run db:roles` → `npm run preflight`.
   Без seed сайт не сможет принять заявку на новые пакеты: preflight это покажет (`birthday_packages_v3_missing`).
3. Сайт: сборка с `NEXT_PUBLIC_GA_ID` (если нужна аналитика) и новый деплой. Сначала платформа, потом сайт.
4. Проверка на живом: `/birthdays`, `/kk/birthdays`, одна тестовая заявка (с пометкой «ТЕСТ»), отмена в CRM.

## Откат
- Сайт: вернуть предыдущий деплой (предыдущая сборка знает старые ID и отправит старые пакеты).
- Платформа: `UPDATE bb.packages SET is_active = true WHERE id IN ('wow-party','magic-party','boom-party');` — история и цены сохранены.
- Новые пакеты деактивировать: `UPDATE bb.packages SET is_active = false WHERE id IN ('happy-party','star-party','boom-bala-party');`

## Ограничения
- Казахская версия: только страница дней рождения, карточки, сравнение, CTA и форма. Шапка, подвал, меню и юридические тексты остаются на русском.
- Календарь доступности (`AvailabilityPanel`) включается флагом `NEXT_PUBLIC_BOOKING_CALENDAR`; он русскоязычный, при включении его нужно локализовать.
- Текст WhatsApp-сообщения формируется на русском.
- Фото комнат — текущие изображения сайта (сгенерированы на основе фото, как написано на сайте); отдельных «реальных фото» из ТЗ в переданной папке нет.
- Миграция 015 идёт после 013. Если ветка с паспкиями (миграция 014) будет слита, её нумерация не пересекается с 015.
