## 2. Риски (по важности)
1. **Юридический, блокирующий production.** Supabase не имеет региона в РК, размещение ПДн за рубежом нельзя считать соответствующим законодательству РК. `PII_INTAKE_ENABLED=0`, `LEAD_PIPELINE=telegram-only`, `CONSENT_FORM_ENABLED=0` оставлять до отдельного решения. Тексты документов с `[ТРЕБУЕТСЯ: …]` (ИП «Аманов»: ФИО, ИИН, адрес, сроки хранения) не утверждены; платформа не даст их опубликовать.
2. **Секреты в Preview.** Если `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` включены для Preview сайта `boombala`, тестовая заявка на Preview уйдёт в рабочую группу. Проверить и выключить Preview-область у этих переменных (раздел 3, шаг 7). До проверки на Preview валидные заявки не отправлять.
3. **Free-тариф Supabase.** Нет скачиваемых бэкапов и PITR, возможна пауза при простое, лимит 500 МБ. Потеря данных на Free = потеря. Для production: платный тариф и расписание `pg_dump`.
4. **Реальное соединение не проверено.** Пулер (порт 6543), TLS с проверкой сертификата, раннер миграций по прямому подключению и параллельные соединения проверены только локально и через SQL (MCP). Нужен `verify:remote` с вашими секретами.
5. **Нет оповещений.** Недоставленные уведомления (`dead`) и падение базы заметят только при ручном просмотре (пункт 25).
6. **Один репозиторий, два проекта Vercel.** Без Ignored Build Step слияние в `main` создало бы production-деплой платформы без переменных. Шаг обязателен (раздел 3).
7. **Часть проверок эмулированная.** Мобильные тесты формы идут в Chromium; iOS Safari проверялся в симуляторе (PR #5). На физических телефонах ручная проверка по чек-листу ещё нужна.
8. **Календарь и новости за флагами.** Включение `NEXT_PUBLIC_BOOKING_CALENDAR`/`NEXT_PUBLIC_NEWS` требует новой сборки сайта (переменные встраиваются при сборке).

## 3. Что сделать вам (точные действия)

### Vercel: создать проект `boombala-platform`
Подключение к Vercel не имеет прав на создание проектов (ответ 403), поэтому вручную:
1. vercel.com → команда `shodymq's projects` → **Add New… → Project** → Import Git Repository `shodymq/boombala`.
2. **Project Name:** `boombala-platform`. **Framework Preset:** Next.js. **Root Directory:** `platform` (Edit → выбрать папку; галочку «Include source files outside of the Root Directory» можно оставить).
3. **Environment Variables** на этом экране не добавлять (сначала создать). **Deploy**. Первый деплой из `main` не соберётся (в `main` ещё нет `platform/`): это нормально.
4. **Settings → Build & Deployment → Ignored Build Step → Custom:** `case "$VERCEL_GIT_COMMIT_REF" in feat/platform-*|release/*) exit 1;; *) exit 0;; esac` (собирать ветки `feat/platform-*` и `release/*`, пропускать `main` и остальное).
5. **Settings → Deployment Protection → Vercel Authentication:** включить для Preview (и для Production, если доступно). **Settings → Domains:** оставить только `*.vercel.app`, `admin.boombala.kz` не добавлять.
6. **Settings → Environment Variables** (Environment: только **Preview**, переключатель Sensitive):
   - `DATABASE_URL` = Supabase `boombala-test` → Connect → **Transaction pooler** (порт 6543). Пароль: Project Settings → Database (Reset database password, показать один раз).
   - `DATABASE_CA_CERT` = корневой сертификат Supabase (PEM, Project Settings → Database → SSL Configuration → Download certificate).
   - `PLATFORM_HTTPS=1`, `PII_INTAKE_ENABLED=0`.
   - `PLATFORM_INTAKE_TOKEN`, `CRON_SECRET`, `PLATFORM_IP_PEPPER`: каждая своя случайная строка (`openssl rand -hex 32`).
   - **Не добавлять:** `MIGRATION_DATABASE_URL`, ключи Supabase `anon`/`service_role`, `TELEGRAM_*` рабочего чата.
7. **Проект `boombala` (сайт), только проверить:** Settings → Environment Variables → у `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` должен стоять **только Production** (убрать Preview и Development). Убедиться, что в Production нет `LEAD_PIPELINE`, `PLATFORM_URL`, `PLATFORM_INTAKE_TOKEN`, `NEXT_PUBLIC_BOOKING_CALENDAR`, `NEXT_PUBLIC_NEWS`, `CONSENT_FORM_ENABLED`.
8. Supabase: **Project Settings → API → отключить Data API**; ключи `anon`/`service_role` нигде не использовать.

После шагов 1–6 напишите мне, что проект создан и переменные заданы (значения не присылайте).

### Проверка реального соединения (запускаете вы или даёте мне локальный доступ)
В `platform/` на доверенной машине (значения только в окружении, не в файлах репозитория):
```bash
VERIFY_REMOTE_CONFIRM=boombala-test \
DATABASE_URL='<Transaction pooler URL>' \
DATABASE_CA_CERT="$(cat supabase-ca.pem)" \
npm run verify:remote
```
Ожидание: `ALL OK`; TLS: «server certificate is VERIFIED»; 12 раундов конкурентного бронирования из независимых соединений дают по одной брони; синтетические строки удаляются сами.
Миграции в будущем (раздел 4) идут отдельно по **прямому** подключению.

## 4. Запуск и проверка (инструкция)

**Локально (полный стек):**
```bash
cd platform && npm run db:local -- start            # свой PostgreSQL на :54330
export DATABASE_URL=$(npm run -s db:local -- url)
npm run db:migrate && npm run db:seed               # схема и каталог
npm run user:create -- --email you@example.com --name "Имя" --role owner
# платформа (prod-сборка): PII_INTAKE_ENABLED=1 PLATFORM_INTAKE_TOKEN=… CRON_SECRET=… TELEGRAM_API_BASE=http://127.0.0.1:3199 SITE_REVALIDATE_URL=http://localhost:3000 npx next start -p 3100
# сайт (флаги встраиваются при сборке): NEXT_PUBLIC_BOOKING_CALENDAR=1 NEXT_PUBLIC_NEWS=1 npx next build
#   LEAD_PIPELINE=dual PLATFORM_URL=http://localhost:3100 PLATFORM_INTAKE_TOKEN=… CONSENT_FORM_ENABLED=1 TELEGRAM_API_BASE=http://127.0.0.1:3199 npx next start -p 3000
npm run e2e:release                                  # 8 сквозных сценариев (сам поднимает заглушку Telegram на :3199)
```
**Миграции на Supabase (вручную, доверенная машина, прямое/сессионное подключение):** `MIGRATION_DATABASE_URL=… npm run db:migrate`. В runtime Vercel `MIGRATION_DATABASE_URL` не добавлять.
**Порядок включения (только после решения о размещении ПДн и вашего разрешения):** тестовая база → Preview платформы с `PII_INTAKE_ENABLED=0` → проверка `verify:remote` → публикация утверждённых документов → Preview с `PII_INTAKE_ENABLED=1` и тестовым Telegram-чатом → внешний планировщик outbox → решение о production.

## 5. Резервные копии
- Проверка восстановления: `DATABASE_URL=… npm run backup:check` (дамп, восстановление в временную базу, сравнение строк/миграций/RLS/индексов/триггеров, удаление временной базы).
- Для Supabase Free: регулярный `pg_dump --format=custom --schema=bb --no-owner --no-privileges "<прямой URL>"` на доверенной машине (раз в сутки, хранить зашифрованно вне Supabase; в дампе будут ПДн, когда появятся реальные данные). Восстановление: `pg_restore --no-owner --dbname "<пустая база>" файл`.
- Для production: платный тариф (ежедневные копии 7 дней) и/или PITR как платное дополнение; решать вместе с вопросом размещения.

## 6. Откат
- **Сайт и платформа:** Vercel → Deployments → предыдущее развёртывание → Instant Rollback (на Hobby доступен откат к непосредственно предыдущему production-развёртыванию).
- **Функции без отката кода:** вернуть переменные в безопасные значения и пересобрать сайт: `LEAD_PIPELINE=telegram-only`, `NEXT_PUBLIC_BOOKING_CALENDAR` и `NEXT_PUBLIC_NEWS` пусто (флаги встраиваются при сборке), `CONSENT_FORM_ENABLED=0`, на платформе `PII_INTAKE_ENABLED=0`. Заявки, сохранённые в базе, остаются.
- **База:** миграции только вперёд и обратно совместимы (добавление, не удаление). Откат данных: восстановление из дампа (раздел 5).

## 7. Мониторинг (минимум для Preview, обязательное для production)
- Пинг `GET <платформа>/api/health` (200 `{ok:true}` или 503) раз в минуту внешним сервисом.
- Просмотр логов Vercel по `event: api.error`, `outbox.send_failed`, `[lead] platform path failed`.
- Админка → Обзор: «Не доставлены после всех попыток» должно быть 0.
- Планировщик outbox: пример `docs/platform/outbox-cron.workflow.yml.example`.
